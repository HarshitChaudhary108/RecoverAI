# Project Guidelines
- Read PROGRESS.md, docs/file_map.md, spec.md and tech.md first. spec.md = behaviour. tech.md = how to build.
- Create or change only the files listed in the session prompt ("Files for this session"). Put every file at the exact path in docs/file_map.md. If you need a file that is not listed, stop and ask me where it goes. PROGRESS.md is updated every session.
- Put business logic in backend/app/. Keep backend/worker/tasks.py thin: it only calls code in backend/app/.
- Do only what this session asks. No extra features. No SMS, no Slack, no RAG, no ORM.
- Use uv for all Python work: `uv add <pkg>` / `uv add --dev <pkg>` to add packages, `uv sync` to install, `uv run <cmd>` to run anything (pytest, uvicorn, celery, scripts). Never use pip, `python -m venv`, or requirements.txt. Commit backend/pyproject.toml and backend/uv.lock.
- All commands must be run from the project root:
  - Worker: `uv run celery -A backend.worker.celery_app worker --pool=solo`
  - Beat: `uv run celery -A backend.worker.celery_app beat`
  - API: `uv run uvicorn backend.app.main:app`
  - Tests: `uv run pytest`
  - Scripts: `uv run python -m backend.scripts.<name>`
- Use ONE import style everywhere: `from backend.app...`, `from backend.worker...`, `from backend.scripts...`. No `sys.path` hacks.
- Use Psycopg 3 with parameterized SQL. Never build SQL with f-strings.
- Never put secrets in code or logs.
- Do not call outside services inside the webhook request.
- Do not guess provider facts. Use docs/provider_notes.md. If it is missing a fact, check the official docs and add it there.
- Tests must run in a temporary database schema, not on real data.
- If you want to do something different from the spec, stop and tell me first.
- End of every session: run the tests, update PROGRESS.md, then tell me (1) what you built, (2) how I can check it, (3) what you were not sure about.
